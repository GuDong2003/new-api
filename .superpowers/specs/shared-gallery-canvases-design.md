# 图库与画布共享保存设计

状态：布局、浏览器优先保存方式和同步删除范围已确认；本说明待整体审阅，业务代码尚未修改。

## 1. 目标和范围

在现有「无限画布 → 我的图库」内提供「图片 / 画布」两个视图。保留绘图与 NAI 两种编辑器，让用户既能看原图，也能回到保存的画布继续编辑。

- 图片、画布节点、参考图和遮罩使用明确的资源关联；图库和画布不能各存一份同一张原图。
- 保留当前编辑器实际支持的提示词、参数、图像、节点位置、连线、参考关系、遮罩和视口。
- NAI 只保存它目前已有的功能，不借此次保存改造增加新的参考图生成能力。
- 单个 new-api 实例，复用现有数据库、私有文件目录和后台清理任务；不新增独立服务、消息队列、分布式协调或对象存储依赖。
- 不扩展内容审计、公开分享、跨用户图库查看、跨画布引用编辑或多人协作。

## 2. 界面

采用用户已确认的可点击预览布局，不把预览 HTML 当成生产代码。

- 顶部保持「绘图 / NAI 画布 / 我的图库」。图库内切换「图片 / 画布」。
- 图片视图采用图片优先的响应式布局，支持搜索、来源筛选、排序和分页加载；卡片显示来源画布。
- 点击图片查看原图与生成详情；点击来源画布打开正确编辑器，定位并高亮目标图片。没有可靠来源关联的历史图片不显示虚假的跳转入口。
- 画布视图显示封面缩略图、名称、类型、修改时间和保存状态；提供新建、打开、重命名、删除。
- 展示「仅本地 / 待同步 / 已同步」；失败或空间不足有明确状态，不把本地写入成功显示成站内已保存。
- 沿用现有中文界面及 i18n，不引入成段英文说明；兼容窄屏、长标题、空状态、加载和错误状态。
- 复用现有 `ConfirmDialog`、`Dialog`、`EmptyState`、`LoadingState`、`ErrorState`、基础控件及原图预览逻辑；只新增画布业务组合，不复制通用交互。

## 3. 保存结构

推荐「一份图像资源 + 轻量画布文档」。分别打包图库和整张画布会重复保存原图；只保留浏览器草稿则无法满足站内保存及其他设备打开的需求。

- 增加画布记录：所属用户、类型、名称、稳定 ID、文档版本、服务端修订号、修改时间、到期时间和状态。
- 文档保存节点、设置和资源 ID，不在服务端文档中再次嵌入已经保存的原图 base64。
- 扩展现有图库资源关联，明确画布 ID、节点 ID 和素材用途。新生成结果从一开始就绑定这些 ID，不能再依赖临时生成任务 ID 猜测节点。
- 同一画布内多处使用同一素材只保存一份原图、计算一次原图数量和原图字节；图库展示直接使用这份资源。画布封面复用已有缩略图。
- 参考图与遮罩是该画布的素材，不混进默认的生成作品列表；其存储空间仍计入配额。
- 每次同步只上传新增或变化的二进制资源；已有资源传 ID。保存文档时校验资源真实存在且属于当前用户和目标画布。
- 保留原始图像字节，不以缩略图代替原图。缩略图作为浏览辅助，其实际字节单独计入同一容量。

这里的「不重复存储」指图库和画布共享同一份站内资源。浏览器离线缓存与站内副本分别承担编辑和同步用途，不能因此取消用户已要求的本地草稿。

## 4. 浏览器优先与同步频率

- IndexedDB 按站点、用户、画布隔离文档和 Blob；两种编辑器可保存多张画布，记录各自最近打开的画布。
- 修改后约 2 秒防抖写入本地。只有 IndexedDB 事务成功，才显示本地已保存。
- 持续编辑时，自动站内同步间隔至少 5 分钟，且仅处理发生变化的画布；没有变化不发送保存请求。
- 离开当前画布、切换页面或主动退出账号时，立即保存本地并尝试同步脏数据；这些离开操作不受 5 分钟定时限制。手动同步同样不受该限制。
- 新生成图片先进入同一份本地文档和待同步队列，图库可以展示本地待同步结果；不再另起一条重复保存原图的即时上传链路。图像生成成功和展示不等待站内同步。
- 主动退出前最多给同步 5 秒；超时仍完成退出，保留已落盘的草稿，不让上传无限阻塞登出。
- 关闭标签页、浏览器退出或进程被结束时不能保证网络上传或最后一次落盘完成。使用离开信号尽力刷新，但以先前成功写入的本地草稿为恢复依据。
- 下次同一用户登录后，先核对站内版本和删除状态，再重试尚未同步的数据。不会借用另一个用户或旧登录会话上传。
- 上游返回临时图片地址时，应在当前会话可访问期间取得原图字节供本地持久化；无法取得时明确提示该素材尚未保全，不能把一个可能过期的 URL 标记为原图已保存。远程获取继续遵守现有安全下载规则。

## 5. 删除：两个视图是同一行为

用户已明确确认以下范围，替代此前「删除画布仍保留图库图片」的建议。

| 用户操作 | 结果 |
| --- | --- |
| 在图库或画布删除一张图片 | 删除这一份图片资源；图库和画布里的对应图片一起消失，画布及其他图片保留。 |
| 删除整个画布 | 删除画布及其所属生成图、参考图、遮罩；对应图库图片一起消失。 |
| 取消将某张图用作参考图 | 只解除该参考关系，不等于删除仍存在的图片节点。 |
| 画布到期 | 按整张画布的删除范围一起清理，不留下图库副本或缺少参考图的半张画布。 |

- 删除前复用确认弹窗说明影响范围。批量删除、清空或替换已同步画布时同样不能绕过提示。
- 删除被用作参考图的图片时，移除相关引用、失效遮罩和连线；已经生成的其他结果图仍保留。
- 删除操作优先于普通自动保存，不等 5 分钟；离线时先在当前浏览器两处移除并记录待同步删除，清楚标记站内删除尚未完成。
- 成功删除后清除当前浏览器相关文件缓存、待上传任务和可恢复该资源的旧快照；迟到的生成结果不得把已删节点或已删画布重新建回来。
- 服务端使用修订号检查和最小删除标记，阻止其他标签页、设备及离线旧草稿重新上传已删内容。标记只含必要 ID/版本，不保留原图、缩略图或提示词副本。
- 已同步记录被删除或到期后，旧草稿不能自动按新记录重新创建；告知用户站内版本已移除。主动导入一份用户自行保留的导出文件属于明确的新建行为。
- 已提交的永久删除不能通过编辑器旧撤销栈恢复。未提交的普通本地编辑仍保留原有撤销能力。
- 文件删除失败时保留待清理状态并重试，实际删除后才释放相应配额；不把删除失败报成空间已释放。
- 服务端不能即时抹除一台离线设备的磁盘缓存；该设备重新联网核对状态后移除对应本地内容，且不得把它重新传回站内。

## 6. 保留期与配额

沿用现有设置页面 `/system-settings/operations/gallery`，扩展文案与统计含义，不再新增一套彼此独立的图库/画布限额。

- 保留期推荐按画布最后一次实际内容修改成功同步起算。图片及参考素材跟随所属画布到期；旧的独立图库图片在建立画布关联前继续按原到期时间处理。
- 只打开查看、切换标签、重复同步、重试同一次保存不续期。视口变化可以被保存，但仅平移/缩放不视为内容修改续期。
- 修改保存期限设置不立即批量缩短已有内容的期限；之后首次实际修改成功同步时采用新期限。界面显示真实到期时间。
- 共用现有每用户图片数量、每用户空间、全站空间限制。数量按实际保存的原图计算，包含参考原图；遮罩作为附属素材只计空间，缩略图不额外算图片张数。
- 空间包括原图、缩略图、参考素材、遮罩和持久化文档/元数据，不因为切换视图重复计算。原有数值配置不自动重置。
- 达到限额或磁盘余量不足时拒绝新增保存；仍允许删除和不增加存储的必要更新。保留上一份完整站内版本与本地草稿，不影响继续生图，不自动删未到期内容腾空间。
- 不新增另一套每张图片或每次保存张数的业务配额；保留已有格式、文档结构、下载超时、引用上传及模型本身的安全/能力边界。
- 沿用现有磁盘余量保护。业务内容配额不是整个 VPS 文件系统占用的精确等价物，不将数据库底层页、索引或其他服务用量算成用户图像空间。

## 7. 同步原子性与边界

- 延续单实例锁保护的存储方式，配合数据库事务提交文档与关联，不引入分布式租约。
- 文档先校验，新增文件按剩余预算逐个流式写入；资源全部就绪后才发布新修订。失败保留旧版本，清理本次未完成文件，不出现「已同步但缺图」。
- 相同保存重试幂等；服务端检查提交的基础修订号，旧版本不能覆盖较新版本或删除结果。
- 不实现通用多端合并引擎。发生并发修改冲突时保留本地草稿、提示重新载入站内版本，不静默覆盖任一方。
- 已删除资源、过期资源、越权资源、畸形文档、超限上传明确拒绝；图片列表、原图读取和画布读取统一检查当前用户所有权。
- 原图通过现有私有鉴权文件接口提供，不暴露本地路径，不增加公开图片 URL。站点管理员也不能借本功能查看其他用户图库。
- 退出/换号时停止原会话请求并撤销内存中的图片 URL；本地保存内容不包含令牌、API Key、会话凭据或认证请求头。

## 8. 兼容与迁移

- 保留已有图库记录、原图及管理员配置；迁移只能增量扩展，不能把缺少关联的历史图片当成无用数据清理。
- 当前每用户一份绘图/NAI 本地文档迁移为各自的一张本地草稿，保留提示词、设置和素材；成功完成新格式本地事务前不丢弃旧格式数据。
- 历史草稿先在本地可用，不在升级时批量上传。用户首次选择将该历史草稿保存到站内时，再做可靠来源映射和同一原图的复用；不能根据图片名称、提示词或时间相近猜关联。
- 不具备可靠关联的历史图库项继续正常显示和下载，但不伪造来源画布。能够确认是同一原图时复用已有文件，不从图库再拷一份到画布目录。
- 新版文档显式记录服务器资源映射，避免再次出现旧任务 ID 与节点 ID 无法对应的问题。
- 数据模型使用现有 GORM 兼容规范，覆盖 SQLite、MySQL、PostgreSQL；不改变日志数据库或审计数据。

## 9. 实现落点与验收

主要扩展 `model/gallery.go`、`service/gallery.go`、`service/gallery-storage.go`、`controller/gallery.go` 与现有图库路由；前端围绕 `features/gallery/`、两个画布的 storage/persistence hooks 和 stores、`routes/_authenticated/canvas/` 组合实现。

验收必须覆盖：

1. 绘图与 NAI 保存、重新打开、源图片定位；参考图、遮罩、参数及已有连线不丢失。
2. 本地 2 秒防抖、5 分钟低频同步、离开刷新、无变化不请求、关闭后恢复及换号隔离。
3. 同一图片在两种视图只占一份原图空间；删单图不删其他图，删画布不残留图库图片。
4. 删除与上传竞态、离线旧草稿、旧版本冲突不会自动复活内容；删除失败不提前释放配额。
5. 保留期、图片数、用户/全站容量及磁盘余量的边界；失败不破坏此前已同步版本。
6. 未登录与越权请求被拒绝，原图接口不泄漏其他用户数据；中文与手机/桌面布局均正常。
7. 受影响前端测试、类型检查、lint 与生产构建；后端聚焦真实行为的回归验证。
8. 真实 SQLite、MySQL、PostgreSQL 的新建库、从当前发布版本升级及重复启动迁移，记录实际版本和结果。

没有真实生图需求的验证使用固定本地图片，不触发付费生成请求。只在验证完成后按用户此前要求提交、推送、创建新 tag 并部署；本设计审阅阶段不发布、不修改 VPS。
