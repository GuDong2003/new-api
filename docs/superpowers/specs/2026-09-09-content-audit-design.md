# 内容审计设计

日期：2026-09-09

状态：待实现前审查

## 1. 目标

新增一个默认关闭的“内容审计”能力。root 在系统设置中打开后，记录开关打开之后全站所有用户的新请求，记录按用户归档，并允许 root 在后台查看：

- 用户发送的文本请求；
- 模型返回的文本响应；
- 图片请求的提示词和生成参数；
- 图片结果地址，以及受大小限制的压缩缩略图。

内容审计与现有用量日志、计费日志、登录审计日志分离。关闭开关不会删除历史记录；历史内容不会被补录。

## 2. 非目标

- 不追溯开关开启前的请求；
- 不把完整请求/响应写入现有 `logs` 表的 `content` 或 `other` 字段；
- 不保存原始图片 Base64 或无上限的原图；
- 不让普通管理员或被审计用户默认查看内容；
- 不让审计失败影响原 API 请求的成功与否。

## 3. 默认策略

| 项目 | 默认值 | 说明 |
| --- | --- | --- |
| 全站记录 | 关闭 | 只有 root 能开启 |
| 保存期限 | 7 天 | 可配置范围 1～30 天 |
| 单条请求上限 | 512 KB | 超出后截断并标记 |
| 单条响应上限 | 1 MB | 超出后截断并标记 |
| 审计总容量 | 512 MB | 只计算审计 payload 和缩略图 |
| 容量提醒 | 80% | 设置页显示警告 |
| 自动保护 | 95% | 暂停新记录，清理任务继续运行 |
| 图片缩略图 | 开启 | 最长边 1024 px，单张不超过 300 KB |

所有限制都应在服务端强制执行，前端设置仅用于修改配置和展示状态。

## 4. 数据和存储

### 4.1 元数据表

新增独立的 `content_audits` 表，至少包含：

- `id`、`created_at`、`expires_at`；
- `user_id`、用户名称快照；
- `channel_id`、渠道名称快照、模型名称、分组；
- `request_id`、`upstream_request_id`、请求路径；
- `kind`（text/image）、`is_stream`、HTTP 状态、耗时；
- 请求/响应字节数、是否截断、脱敏版本；
- payload 文件引用、缩略图文件引用、图片 MIME 类型；
- 错误信息和清理状态。

表中只保存检索所需的元数据和相对文件引用，不保存大段正文或图片二进制。

### 4.2 Payload 存储

正文和图片缩略图存放在独立的内容审计目录，不复用请求体缓存目录，避免清理缓存时误删审计内容。目录文件名使用随机 ID，不把用户输入直接放入路径。

存储层通过接口隔离，首期实现本地文件存储，后续可替换为对象存储。payload 使用压缩格式；文件权限只允许服务进程读写，HTTP 只能通过带权限的审计接口读取，不能直接暴露目录。

如果配置了现有的加密密钥，payload 在落盘前加密；密钥缺失时仍保持功能可用，但设置页明确提示“仅依赖主机文件权限保护”。

## 5. 捕获流程

1. 请求经过认证并完成渠道/模型解析后，若全站开关开启且未触发容量保护，创建审计上下文。
2. 捕获客户端看到的请求语义，而不是包含上游密钥的内部请求。请求体从现有可重放 BodyStorage 读取，避免重复读取网络流。
3. 对文本请求记录脱敏后的 JSON；流式响应按输出顺序拼接，达到响应上限后停止追加但继续把响应发送给客户端。
4. 对图片请求记录 prompt、模型、尺寸、质量、模式等参数，不把输入图片的完整 Base64 写入正文。
5. 响应完成后，在响应上限内保存客户端可见的完整响应内容，并记录状态、耗时等元数据。图片响应中的 `url` 保存为结果地址；`b64_json` 直接解码生成缩略图后丢弃原始 Base64。
6. 审计写入采用 best-effort 异步队列。队列满、磁盘不足或写入失败时只记录系统告警，不阻断或改写用户请求响应。

## 6. 图片缩略图安全规则

- 仅接受 `http`/`https` 图片地址；禁止 localhost、内网、链路本地、保留地址和非标准重定向目标，防止 SSRF；
- 下载设置连接超时、总超时和响应大小上限；只接受 `image/*`，并校验真实文件类型；
- 按最长边 1024 px、质量上限压缩为 WebP/JPEG，单张超过 300 KB 时继续压缩或放弃保存；
- 下载失败时仍保留结果地址和失败原因，后台显示“缩略图不可用”；
- 只通过 root 授权的 API 返回缩略图，不返回本地真实路径。

## 7. 脱敏规则

请求头和结构化 JSON 中的以下字段统一替换为 `[已隐藏]`：`Authorization`、`api-key`、`x-api-key`、`cookie`、`set-cookie`、`proxy-authorization`、`password`、`secret`、`token`、`access_token`、`refresh_token` 等。

脱敏只针对凭据和二进制载荷，不修改用户正常的文本 prompt 或模型回复。每条记录保存脱敏版本号，便于将来升级规则。

## 8. 权限和后台页面

### 8.1 设置

在“系统设置 → 运维/维护”增加“内容审计”区域，仅 root 可见、可修改：

- 全站开启/关闭；
- 保存期限；
- 单条请求/响应上限；
- 总容量上限；
- 是否保存图片缩略图；
- 当前占用、记录数、最早过期时间、最近清理时间和自动暂停原因。

### 8.2 查看

增加 root-only 的“内容审计”页面，支持按用户、时间、渠道、模型、请求 ID、内容类型和状态筛选。详情页分开显示请求、响应、截断提示、图片参数和缩略图；原始结果地址只作为辅助信息展示。

每次查看正文、下载缩略图或删除记录，都写入现有安全审计日志，记录操作者、记录 ID 和操作类型，不把正文复制进安全审计日志。

## 9. 清理和容量保护

- 后台任务按小时删除 `expires_at` 已到期的记录及对应文件；
- 删除采用先删文件、再删元数据；发现孤儿文件时由清理任务回收；
- 达到 80% 总容量时仅告警；达到 95% 时暂停新内容记录；
- 清理后回到 80% 以下才恢复自动记录；root 也可以手动清空过期/指定记录；
- 不触碰 PostgreSQL、Redis、Docker 缓存或用户备份目录。

## 10. 错误处理和隐私边界

- 审计失败不影响代理请求、计费或用户响应；
- 记录状态为“未完整保存”并保留失败原因，便于 root 排查；
- 审计 API 禁止通过 URL 参数传递正文；
- 所有内容接口都需要 root 权限和正常会话，拒绝 API token 直接读取审计正文；
- 默认不在 DEBUG 日志中重复打印已捕获正文，避免同一内容出现两份。

## 11. 测试要求

后端测试覆盖：

- 开关关闭时不创建数据库记录或文件；
- 开关打开后按用户和请求 ID正确归档；
- 流式响应拼接、截断和状态记录；
- 敏感字段脱敏，普通文本保持原样；
- 图片 URL 校验、SSRF 防护、缩略图尺寸和字节上限；
- TTL 清理、容量 80%/95% 阈值、孤儿文件回收；
- root 权限和查看审计日志；
- 存储失败不改变 API 响应。

前端测试覆盖：

- root-only 页面和设置保存；
- 用户/时间/模型/请求 ID筛选；
- 截断状态、缩略图失败和容量保护提示；
- 请求/响应折叠显示与复制行为。

## 12. 发布策略

先完成数据库迁移、存储层、捕获和清理测试，再接入设置页和查看页。发布后保持默认关闭，不影响现有用户和现有用量日志；root 在确认容量和权限后手动开启。
